# 오늘 모해 3D 시제품 검증 보고 · 2026-10-11

## 판단

**지리적 위치를 X/Y로 유지하고, 선택한 지표를 Z 높이로 표현하는 실제 3D 탐색은 구현 가능하며 로컬 작동까지 확인했다.** 카메라 원근, 장소 선택과 초점 이동, 높이 전환, 바닥 위치 연결을 구현했다. 현재 수준은 탐색 UX를 직접 검토할 수 있는 기술 시제품이다. 운영 서비스에 연결된 개인화 추천 완성본은 아니다.

배포하지 않았다. 기존 public 서비스와 운영 데이터는 수정하지 않았다. 시제품은 `previews/three/`에 있으며 기존 빌드는 `public/`만 복사하므로 현재 운영 빌드에 포함되지 않는다.

실행: 프로젝트에서 `node previews/three/server.mjs`, 접속 `http://127.0.0.1:4174/`. 서버는 127.0.0.1에만 바인딩한다. 키·GPS·외부 API 없이 동작하며 종료 후 재실행할 수 있다.

## 실제로 만든 범위

| 요소 | 현재 구현 | 검증/한계 |
|---|---|---|
| 공간 | Three.js r186 / WebGL2 / PerspectiveCamera | 로컬 브라우저 렌더 확인. WebGPU는 적용하지 않음 |
| 좌표 | X 동쪽, Y 북쪽, Z 점수. 호수공원 기준 국소 Mercator | 원본 좌표 유지, 카메라가 회전하면 화면 방위는 함께 회전 |
| 방향 복원 | 북쪽 위 시점 / 전체 보기 | 버튼 동작 확인. 북쪽 위도 원근 카메라로, 정식 2D 지도는 아님 |
| 높이 | 가상 인지도 / 관심사 일치 / 평면 전환 | 선택 상세에서 94 → 관심사 일치100 → 평면0 확인 |
| 위치 이해 | 각 장소의 바닥 고리와 수직선, 1km 간격 격자 | 도로·이동 경로나 건물 고도가 아님 |
| 선택 | 사진·그래픽·이름·목록에서 선택, 카메라 초점 이동 | 화면 이름/목록 클릭과 상세 확인. 원형 사진 가공은 미적용 |
| 조작 | OrbitControls 회전·줌·팬, 자동 회전 토글 | 컨트롤 구현. 실기기 핀치/드래그 전체 동작 시험은 남음 |
| 좁은 화면 | 기본 페이지 스크롤, 별도 터치 탐색 토글 | ON/OFF 상태 및 모바일 상세 확인 |
| 겹침 | 이름 간 충돌 시 일부 숨김, 목록으로 전체 접근 | 사진/객체 자체의 중첩, 깊이별 가림, 군집화는 후속 |
| 접근성 | HTML 버튼·목록·선택 상세, reduced-motion 처리 | 스크린리더와 실제 감소 모션 환경 검증은 남음 |
| 자원 관리 | 화면 밖/숨김 시 렌더 생략, 해제, context loss 안내 | 코드 구현. GPU 강제 중단/복구 실험은 미수행 |

3D 공간의 노드는 사진/그래픽이 카메라를 바라보는 sprite 방식이다. 실제 원근·높이·카메라 이동이 있지만, 도시의 건물이나 지형을 입체 모델링한 디지털 트윈은 아니다. 몰입감을 더 높이려면 이 공간 안에서 선택 노드 확대, 사진 품질, 카메라 동선, 배경과 음영을 발전시키면 된다.

## 사용 데이터와 경계

온톨로지 파일럿의 장소16개 중 좌표 있는10개만 사용했다. 객체 UUID와 좌표를 그대로 가져오며 좌표 없는6개는 이유와 함께 목록으로 공개했다. 허가된 기존 장소사진3종을 사용하며 출처·저작자·라이선스를 상세에서 표시했다. 이 사진은 현재 행사 사진이 아니다.

시제품 데이터는 `data/ontology/pilot.json`에서 읽어 `previews/three/build-data.py`로 생성한다. 주제 태그는 시제품 수동 편집값이며 운영 온톨로지 분류 확정값이 아니다. 인지도는 수동으로 배정한 **가상 점수**이며 외부 인기 통계를 흉내 낸 사실값으로 저장하지 않는다. 관심사 일치는 선택한 주제와 같으면100, 아니면0인 공개된 간단한 규칙이다.

기준 위치는 공개 장소인 호수공원이다. 사용자의 실제 위치를 읽거나 전송하지 않았다. 장소 운영·예약 가능 여부를 검증한 화면이 아니므로 현재 방문 가능성을 보장하지 않는다. 객체 사이의 다음 행동/코스 연결은 구현하지 않았다.

## 운영 데이터 구조 제안

핵심은 **Z를 장소의 고정 속성으로 저장하지 않는 것**이다. 같은 장소도 사용자·시각·선택 지표에 따라 높이가 달라진다. 장소 좌표는 사실 원장에, 평가는 근거와 계산 결과에, 화면상의 높이는 렌더러에 둔다.

| 계층 | 주요 필드 제안 | 역할 |
|---|---|---|
| Object / Place | object_id, latitude, longitude, location_role, source assertion | 객체 정체성과 위치 사실 |
| MetricDefinition | metric_id, meaning, unit, scope, normalization_version | 인지도·관심도·선호도의 의미 정의 |
| MetricObservation | object_id, metric_id, value, provider, source_id, observed_at, window_start/end, sample_size, quality_state | 조회·저장·방문 의향 등 집계 근거. 수집 권리 확인 필요 |
| ScoreResult | object_id, metric_id, score, confidence, computed_at, expires_at, cohort/context, algorithm_version, evidence_ids | 재현 가능한 평가 결과 |
| PreferenceContext | session/context_id, explicit_interests, consent/state | 일차적으로 명시 선택. 학습형 프로필은 별도 후속 |
| ViewProjection | object_id, x, y, z, metric_label, score_state | 화면 조회 응답에서 계산. 원본 사실과 분리 |

위 표는 후속 설계 제안이며 운영 DB 마이그레이션은 실행하지 않았다. 객체 UUID로 연결하므로 Three.js/2D 지도 교체가 원장 변경을 요구하지 않는다.

인지도와 선호도를 하나로 섞는 것은 초기에는 피하는 편이 좋다. '잘 알려진 곳'과 '내가 좋아할 곳'은 다른 질문이다. 사용자가 높이 기준을 선택하게 하고, 선택한 장소에 근거를 표시한다. 나중에 혼합점수를 쓸 때만 가중치·버전·설명을 함께 저장한다.

**데이터 없음은 0점과 다르다.** 운영에서는 근거 없는 인지도를 unknown으로 두고 점수 미확인 표시를 해야 한다. 이번 선호도0은 공개된 규칙상 주제 불일치라는 뜻이다. 실제 낮은 인기와 자료 없음이 같은 바닥으로 보이지 않게 운영 UI를 설계해야 한다.

정규화 범위도 중요하다. 사용자가 지도를 조금 이동했을 때 화면 안 최고점만 기준으로 재정규화하면 같은 장소가 이유 없이 높아진다. 고정된 지역/기간 집단 또는 명시된 절대 기준을 사용하고 점수 범위와 산정 기간을 보여주는 것이 적절하다.

## 어느 수준까지 발전시킬 수 있는가

1. **현재: 10개 연구 장소의 몰입형 탐색 실험.** 실제 장소 좌표와 가상/규칙 점수로 시각 체험을 검토한다.
2. **다음: 기존 서비스에 선택 가능한 3D 탐색 연결.** 공통 조회 결과를 2D 지도·3D·목록이 소비하고, 현재 필터·선택·상세 흐름을 공유한다. 좁은 화면은 전체 화면 탐색과 종료 동작을 보강한다.
3. **그다음: 근거 기반 높이.** 허용된 집계지표와 명시적 관심사를 연결하고 unknown/만료/적은 표본을 표시한다. 운영 데이터 없이 '실제 인기순'을 출시하지 않는다.
4. **후속: 객체·액션 연결.** 장소 선택 뒤 먹기·마시기·쉬기 등의 다음 후보를 띄운다. 이동 경로는 별도 경로 데이터, 행사 참여 가능성은 회차·입장 조건으로 판단한다. 화면 선만으로 관계를 생성하지 않는다.

수백·수천 객체도 기술적으로 확장할 방법은 있지만 이번에는 성능을 입증하지 않았다. 화면에 보이는 후보 제한, 지리 군집, 사진 텍스처 예산, 거리별 상세도, 반복 도형 배치 등을 적용하고 30/100/300개 단계로 실측해야 한다. 서로 다른 사진을 단순히 InstancedMesh로 바꾸는 것만으로 모든 비용이 해결되지는 않는다.

- `node --check previews/three/app.js`: 통과.

- 남은 검증: 실기기 iOS/Android 터치·발열·배터리, Safari/저사양 GPU, WebGL 불가 폴백, 감소 모션·스크린리더, 노드 대량 성능, 사진/표식 중첩 해소.

**다음 결정은 이 시제품에서 높이 표현과 카메라 경험이 사용자가 원하는 몰입감을 주는지 확인하는 것이다.** 그 판단 후 기존 화면에 연결하고, 인지도 실데이터 정의와 수집 계약을 별도로 진행한다. 사용자 검토 전 배포하지 않는다.
