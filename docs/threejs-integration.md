## 최신 변경 · Z축 카테고리 층 (2026-10-11)

사용자 지시에 따라 관심사 점수 높이와 높이 기준 선택을 제거하고, 현재 행사 원장의 category로 고정 층을 구현했다. 낮은 층부터 축제(1.5), 공연(3.3), 전시(5.1), 체험(6.9). 이 숫자는 렌더링 좌표이며 실제 고도·인기도·노출 순위가 아니다. 분류 누락/새 값은 분류 미확인(0.3)으로 분리하며 원본 값을 보존한다.

동일 장소의 복수 분류는 장소 ID·X/Y를 그대로 유지하고 카테고리별 표시 노드를 만든다. 표시 노드의 events는 해당 카테고리만 포함하므로 클릭은 그 층의 행사로 연결된다. 최초 조회 전체 원장232행사: 축제64/공연74/전시22/체험72. 위치 그룹101곳 중 복수 분류6곳, 층별107표시. 이 수치는 전체 저장 자료의 변환 검증이며 오늘 방문 후보 수와 다르다. 날짜/기존 후보 필터는 그대로 적용한다. 상단 UI의 세부 topic과 별개로 현재 event.category 4종을 사용했으며, 카페/식당에 좌표나 행사 분류를 임의 부여하지 않았다.

검증: 107테스트 통과, 외부 수집 없는 빌드 통과. 전체 원장의 장소-행사 연결 무손실 회귀 검증 포함. 실제 로컬 화면에서 축제3/공연1/전시2/체험0 표시, 공연 층 고양아람누리 → 카르멘 상세 확인. 모바일 innerWidth354/scrollWidth341로 가로 넘침 없음, 관찰 콘솔 오류/경고0. 증빙 qa/category-layers.png 및 category-layers-mobile.png. 복수 분류 분리는 단위 테스트와 전체 저장 자료 변환으로 확인했으며, 오늘 화면의 동일 장소 복수 층 클릭은 별도 실측하지 않았다. 배포 안 함.

# 오늘 모해 3D 서비스 연결 · 2026-10-11

## 반영

기존 public/app.js의 장소 그래프 렌더러를 public/spatial-view.js로 교체했다. Three.js를 지연 로딩하고, 기존 필터·날짜·출발지·장소 그룹·선택·상세 콜백을 그대로 소비한다. 시제품의 가상 인기 점수는 운영 화면에 넣지 않았다.

- 기본 3D 위치 표시. 관심 활동을 선택하면 관련 행사 하나 이상이 있는 장소100, 아닌 장소0으로 Z 높이를 변경한다. 학습된 선호도·인지도·입장 가능성 점수가 아니다.
- 동서남북은 Mercator 기반 실제 좌표로 고정. 기준점은 선택한 출발지, 없으면 지역 중심. 수직선은 위치 표시이며 경로가 아니다.
- 사진/이름/접힌 장소 목록에서 선택하면 기존 상세와 카메라 초점 이동을 연결한다. 같은 장소의 행사 선택은 기존 상세 UI를 사용한다.
- 북쪽 위·전체 보기·자동 회전·2D 복귀를 지원한다. 모바일은 명시적으로 터치 탐색을 켠 동안만 제스처를 소비한다.
- 한국어/영어/일본어/중국어 UI 문구. 3D 실패 시 기존 ForceGraph 2D 폴백. renderer dispose, 숨김 렌더 생략, reduced-motion 대응.
- Three.js 0.186.0을 public/vendor/three186에 MIT LICENSE와 함께 보관. OrbitControls의 bare import만 로컬 상대 경로로 수정.
- 기존 네이버 지도 전환 코드 유지. 로컬 서버에 지도 키를 로드하지 않았으므로 실제 네이버 지도 SDK 동작은 이번 검증 대상 밖이다.
